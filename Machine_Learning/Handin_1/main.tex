\section*{PART 1: Logistic Regression}

\subsection*{Theory}

\subsubsection*{Question 1: Running Time of Mini-Batch Gradient Descent}
The running time depends in the number of epochs, since each epoch takes $\mathcal{O(n)}$ time to shuffle and indices the samples, and then it's separated into batches $\frac{n}{B}$ where it takes the gradient and updates the weights, which takes $\mathcal{O}(B \cdot d+d)$ time where $(d)$ is the number of features for each sample, this can simplifies to $\mathcal{O}(B \cdot d)$ and if we sum over all the batches we get a running time $\mathcal{O}(n \cdot d )$ for each epoch, and over all epochs the total running time for mini-batch GD is
\[
\mathcal{O}(epochs \cdot n \cdot d)
\]
\subsubsection*{Question 2: Sanity Check (Pixel Permutation)}
The placement and ordering of the pixels don't matter since the logistic regression treats each pixel independently as it's own feature with it's own weight, so the inner product is still $w^Tx = \sum_i w_ix_i$ which means the shape and order has no affect on the performance. 

\subsubsection*{Question 3: Linearly Separable Data}
If the data linearly separable, the weights diverges to infinity ($\|w\| \to \infty$), since if the data is separable it implies that there is some weight $w'$ such that $y_i(w'^Tx_i) > 0$ for all $i$, and if we scale $w'$ with some constant $c >0$ we get a negative log-likelihood cost
\[
\lim_{c \rightarrow \infty} E_{in}(cw') = \lim_{c \rightarrow \infty} \frac{1}{n} \sum_{i = 1}^n \ln(1+e^{-cy_iw'^{T}x_i}) = 0
\]
and gradient descent keeps taking steps that increase $||w|| \rightarrow \infty$ without converging on a single weight.

\section*{PART 2: Softmax}

\subsection*{Theory}

\subsubsection*{Question: Running Time of Softmax Implementation}
Let $K$ be the number of classes, $n$ the number of training samples, $d$ the number of features, $B =$ mini-batch size, and epochs the number of training epochs.
\\\\
Cost and Gradient: For each mini-batch, the algorithm calculates a score for each class and converts the scores into probabilities using the softmax function. It then compares the predicted probabilities with the correct labels to calculate the cost. The gradient is calculated to determine how the weights should be updated to reduce the cost. This takes $\mathcal{O}(B\cdot d\cdot K)$ time per mini-batch. for the entire dataset it takes $\mathcal{O}(n\cdot d \cdot K)$ time
\\\\
Total running time of Mini-Batch Gradient Descent\\
During each epoch, the algorithm shuffles the data, processes all mini-batches, updates the weights, and calculates the cost for the entire dataset. This takes $\mathcal{O}(n\cdot d \cdot K)$ time per epoch and the total running time is $\mathcal{O}(epochs\cdot n\cdot d \cdot K)$ time
\\\

def cost_grad(self, X, y, W):
    Yk = one_in_k_encoding(y, self.num_classes)
    n = X.shape[0]
    P = softmax(np.dot(X, W))
    cost = -np.sum(Yk * np.log(P)) / n  # Average NLL cost
    grad = np.dot(X.T, P - Yk) / n      # Gradient of average NLL
    return cost, grad

def fit(self, X, Y, W=None, lr=0.01, epochs=10, batch_size=16):
    if W is None: W = np.zeros((X.shape[1], self.num_classes))
    self.history = []
    n = X.shape[0]
    for epoch in range(epochs):
        perm = np.random.permutation(n)
        for i in range(0, n, batch_size):
            b = perm[i : i + batch_size]
            _, grad = self.cost_grad(X[b], Y[b], W)
            W -= lr * grad
        epoch_cost, _ = self.cost_grad(X, Y, W)
        self.history.append(epoch_cost)
    self.W = W
\end{lstlisting}
